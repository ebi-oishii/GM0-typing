# GM0-typing — 評価防衛型タイピングゲーム

> あなたの評価はタイピング数で決まる（らしい）。

エンジニアの生産性をタイピング量で測る会社が現れたAI時代。
コードはAIが書く。ならば人間は、**AIが働いている間に打鍵数を稼ぐしかない**。

GM0-typing は [herdr](https://herdr.dev) のようなターミナルマルチプレクサでペインを分割し、
**右でAIエージェントを働かせながら、左で入力数を稼ぐ**ための TUI タイピングゲームです。
隣のペインで動くAIの状態をリアルタイムに監視し、ゲームルールに反映します。

```
┌──────────────────────────┬──────────────────────────┐
│  GM0-typing ─ 評価防衛型タイピング │  $ claude                │
│                          │                          │
│  申告用入力数 12,345 打     │  ⏺ リファクタリング中...    │
│  倍率 x2（AI 1体が稼働中）   │                          │
│                          │                          │
│  評価 [████████░░] 82     │                          │
│  ╭─────────────────────╮ │                          │
│  │ git rebase -i HEAD~3│ │                          │
│  ╰─────────────────────╯ │                          │
└──────────────────────────┴──────────────────────────┘
```

## ゲームルール

サボりではありません。これは評価防衛です。

| 状況 | 効果 |
|---|---|
| AIが `working` | 打鍵カウント倍率アップ（**x1 + 稼働AI数**。並列で働かせるほど稼げる） |
| AIが `blocked` / `done`（あなたの対応待ち） | **倍率 x0・入力ロック**。「⚠ 業務連絡」が出て、AI対応するまで打鍵はカウントされない |
| **AIのペインで指示を入力中** | **⌨ 評価上昇**。指示出しは立派な打鍵です。バーがぐんぐん回復する。**AIが回答を生成している最中の打ち込みも検知**（herdr 連携時のみ・下記参照） |
| AIのペインを見ているだけ | **減衰**。ここでの評価基準はタイピングです。眺めるのは打鍵ではありません |
| **評価メーターが 0** | **🏢 出社回帰**。タイピング量の低下が人事に検知され、リモートワーク権限剥奪。`enter` で再出社して挽回（回数は日次成績に記録される）。**出社回帰のまま退勤すると、打鍵数に関係なく査定は最低評価 F「出社回帰」** |
| **AIはいるが誰も働いていない**（ジョブ完了後など） | **💤 倍率 x0・入力ロック**。「AIが暇しています」— 次のタスクを振って working にするまで遊べない。AIを遊ばせて自分が遊ぶのは二重のサボり |
| AIなし（監視対象ゼロ） | 倍率 x1 のソロ稼働モード |

指示入力の検出について: herdr にキー入力イベントの API はないため、フォーカス中の
エージェントペインの**入力欄領域（画面下部の最後の `❯` 行から下）**をポーリングごとに
ハッシュ比較し、変化をもって入力中と推定しています。誤検知対策:

- 出力・スピナー・トークンカウンタは入力欄より上に描画されるため対象外。これにより
  **AIが回答を生成中でも、入力欄への打ち込みだけを分離して検知**できる
- 画面最下行は Claude Code などのステータスバーでヒントが自動回転するため、ハッシュから除外
- 入力欄（`❯`）を特定できない画面では画面全体で判定し、生成中は判定を停止する
  （出力で画面が動くだけで上がってしまうため）

- **申告用入力数**: 倍率込みのKPI。人事に報告する数字はこちら
- **実測打鍵数**: 本当の数字。誰にも見せてはいけない
- **評価メーター**: 手が止まると減衰。AIを待たせて放置するとさらに速く減る。打鍵で回復
- **査定ランク**: 日次の申告用入力数で C → B → A → S → SS（日をまたいでもその日の成績は永続化）
- お題は現場の呪文（git / docker / kubectl）、エンジニアの伝統芸能、AI時代の処世術、そして実際のコード片（Go / TypeScript / Python / Rust / SQL / Java）から出題
- お題クリアでボーナス（倍率が掛かる）。ペーストによる水増しは1イベント1打鍵しか受理しない
- `tab`: お題スキップ / `esc`: **休憩**（プロセスは殺さず時を止める。評価メーター凍結・打鍵は受理されない。もう一度 `esc` で業務再開） / `ctrl+c`: **退勤**（終了してサマリ表示）

## ビルドと起動

```sh
go build -o gm0-typing .
./gm0-typing
```

## herdr との連携（推奨）

herdr のペイン内で起動すると自動で連携します（`HERDR_ENV=1` を検出）。
同じワークスペースの全ペインをポーリングし、`claude` / `codex` などの
エージェントの `agent_status` を倍率と警告に反映します。設定は不要です。

```sh
# herdr 内で: ペインを分割して右でAIを起動、左で稼ぐ
herdr pane split --current --direction right
herdr pane run <new-pane-id> "claude"
./gm0-typing   # 元のペインで
```

## herdr 以外での連携（Claude Code hooks / tmux など）

ステータスファイル経由で任意のツールから状態を通知できます。

```sh
./gm0-typing --status-file ~/.local/share/gm0-typing/status.json   # デフォルトと同じ
```

ファイル形式（10分以上更新がないファイルは無視されます）:

```json
{"agents":[{"name":"claude","status":"working","task":"テスト修正中"}]}
```

`status` は `working` / `blocked` / `done` / `idle`。

Claude Code の hooks から自動通知するには `~/.claude/settings.json` に:

```json
{
  "hooks": {
    "PreToolUse": [{"matcher": "", "hooks": [{"type": "command", "command": "/path/to/tui-typing/scripts/claude-hook.sh working"}]}],
    "Notification": [{"hooks": [{"type": "command", "command": "/path/to/tui-typing/scripts/claude-hook.sh blocked"}]}],
    "Stop": [{"hooks": [{"type": "command", "command": "/path/to/tui-typing/scripts/claude-hook.sh done"}]}]
  }
}
```

## オプション

| フラグ | 説明 |
|---|---|
| `--status-file PATH` | ステータスファイルの場所（デフォルト: `~/.local/share/gm0-typing/status.json`） |
| `--no-herdr` | herdr 連携を無効化 |
| `--poll DURATION` | AI状態のポーリング間隔（デフォルト: `2s`） |

日次成績は `~/.local/share/gm0-typing/stats.json` に保存されます。
